# S-3 · Effort on resume (M0-14)

Class HARD · manual (Billy on his Mac) · ADR-008 · ACs AC-M0-13 (S-3), AC-F010-10 · encoded later by `chain::effort_on_resume_branches` (M3-14).

**Question.** Does `claude --resume <uuid> --effort <level>` run the resumed session at `<level>`?

## Run

```bash
pnpm spikes s3 --dry-run         # prints the three argv lines, no tokens
pnpm spikes s3                   # A: new session --effort low; B: --resume <uuid> --effort xhigh (y/N first)
pnpm spikes s3 --level max       # optional: another level on resume (max and ultracode are not valid for effortLevel)
```

Two one-word sessions in `$TMPDIR/foreman-spikes/s3/work` (plan mode, model `opus`, prompt "Reply with the single word: ok"). When Claude answers, type `/exit`. The instrument is the hook input field `effort.level` (documented for `Stop`, `PreToolUse`, `PostToolUse`, `SubagentStop`) and `$CLAUDE_EFFORT`, both logged. Phase A proves the instrument reads the level of a fresh session; phase B resumes the same session id with a different `--effort`. If B does not match, phase C resumes with `effortLevel` in the `--settings` file and no `--effort`.

Manual cross-check: while phase B is open, type `/effort` with no argument only to read the slider (press Escape; do **not** pick a level, because `/effort <level>` saves your default). Record what it shows.

## Pass and fail

- Pass: phase B's `Stop` reports the requested level and `SessionStart` shows `source: resume` with the original `session_id`.
- Fail: it reports another level (the Opus 5.5 default is medium; phase A's level would mean the resume restored the old one).
- Documented background to compare against (code.claude.com model-config, checked 2026-10-20): `--effort` accepts low, medium, high, xhigh, max, ultracode for the session; `effortLevel` accepts low, medium, high, xhigh only and, in `--settings`, applies to every model; the page does not say how effort is restored on `--resume`.

## Decision rule

| Branch | Condition | Foreman does | Documents changed |
| --- | --- | --- | --- |
| Pass | phase B at the requested level | passes `--effort` on resume | ADR-008 ("Effort on resume (S-3)": pass); `docs/scope.md` AC-F010-10 records "flag"; M3-14 test `chain::effort_on_resume_branches` encodes "flag" |
| Fail 1 | B wrong, C (`effortLevel` via `--settings`) at the level | writes `effortLevel` into the run settings file | ADR-008; AC-F010-10 records "settings"; `docs/adr/ADR-021` run settings contents and `run_settings::contents_snapshot`; M3-14 |
| Fail 2 | B and C wrong, or level is `max`/`ultracode` | shows the `/effort <level>` line with the warning that it saves as Billy's default; never types it | ADR-008; AC-F010-10 records "slash"; the launch-preview copy in `docs/design` (warning text); M3-14 |

If B passes for `xhigh` but you also use `max` or `ultracode` in templates, run `--level max` once: a fail there with a pass for `xhigh` means Fail 2 applies to those levels only.
