# S-12 · PATH in a Finder-launched build (M0-17)

Class HARD · manual (Billy on his Mac) · ADR-007 · threat T-019 · ACs AC-M0-13 (S-12), AC-F019-13, AC-F019-14 · re-checked in M4-14.

**Question.** A Finder-launched app gets launchd's minimal PATH, not Terminal's. With the PATH Foreman builds per MASTER-SPEC §6 and ADR-007 item 5 (`/etc/paths`, `/etc/paths.d/*`, `/opt/homebrew/bin`, `/opt/homebrew/sbin`, `~/.cargo/bin`, the pnpm home `~/Library/pnpm`; every entry absolute, existing, a directory, not world-writable; **no** login-shell capture), do `claude`, `git`, `node`, `pnpm` and `cargo` resolve and run?

## Run (zero tokens)

```bash
pnpm spikes s12              # builds the §6 PATH, resolves and runs the five tools, captures a LaunchServices PATH via a stub app
pnpm spikes s12 --finder     # the same, but you double-click the stub in Finder (the faithful way)
pnpm spikes s12 --from-file env.txt   # skip the stub and read the output of `env` you captured yourself
```

How it gets "the PATH a Finder-launched app sees" without `launchctl`: it writes a tiny unsigned bundle `FM Spike PATH.app` in the sandbox whose executable is `/usr/bin/env > <file>` (ad-hoc signed on a best-effort basis) and starts it through LaunchServices. `open -n -W` is the default; `--finder` reveals the bundle and waits for your double-click (right-click, Open, if Gatekeeper complains). A LaunchServices-launched process receives launchd's environment, not Terminal's. If the stub will not start on your macOS, make an Automator app with a "Run Shell Script" action `env > ~/Desktop/finder-env.txt`, double-click it, and pass the file with `--from-file`.

For each tool the runner prints: where it resolves on the §6 PATH (claude and git also via ADR-007's fixed candidates `~/.local/bin/claude`, `/opt/homebrew/bin/claude`, `/usr/bin/git`, `/opt/homebrew/bin/git`), the first line of `<tool> --version` run with exactly that PATH, the script's shebang if any (an npm-installed `claude` starting `#!/usr/bin/env node` fails when `node` is not on the PATH), where your terminal PATH finds it, and where the Finder-only PATH finds it.

## Limits (read before trusting a PASS)

1. The stub is not the Foreman release build. AC-F019-14 (manual, M4-14) re-checks with Doctor's PATH display in the real app. For an extra check now, launch the M0-10 release build from Finder and, if the scaffold prints or logs its environment, compare it with the stub's.
2. The §6 PATH is re-implemented here from the spec text, not by the Rust code (which does not exist yet).
3. "Not inside a registered project" (SR-05) cannot be applied: there is no registry yet.
4. A tool that exists only through a version manager (nvm, fnm, volta, asdf, mise) or a custom prefix set in a shell profile will FAIL on purpose: that is exactly the S-12 fail branch.
5. `git` at `/usr/bin/git` is the Command Line Tools shim; if the tools are not installed the runner skips running it instead of triggering the install dialog.

## Pass and fail

- Pass: all five tools resolve on the §6 PATH (or via the fixed candidates for claude and git) **and** run.
- Fail: any of them does not resolve or does not run.
