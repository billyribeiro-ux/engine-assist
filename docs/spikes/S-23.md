# S-23 · `claude --desktop --resume` (M0-18)

Class HARD · manual (Billy on his Mac) · ADR-008 · threat T-030 · ACs AC-M0-13 (S-23), AC-F024-03, AC-F010-15 · encoded later in M4-29.

**Question.** `claude --desktop --resume <uuid>` hands a CLI session to Claude Desktop. When Desktop continues it, does it append to the same transcript file (shared), or copy the conversation into its own session (copied)?

Needs Claude Desktop installed and signed in to the same account as the CLI.

## Run

```bash
pnpm spikes s23 prepare      # one tiny session (tokens, y/N), snapshots the transcript, prints the Desktop steps
# ...do the Desktop steps below...
pnpm spikes s23 check        # compares the transcript and Desktop's data folder with the snapshot
```

1. `prepare` starts a plan-mode session `fm-s23` with `--session-id <uuid>` in `$TMPDIR/foreman-spikes/s23/work`, asking it to remember a code word and reply "ok". Type `/exit` after the answer. It records the transcript's size and SHA-256, the other transcripts in the folder, and a marker string (`S23-MARKER-…`).
2. In a terminal run the printed `cd '<work>' && claude --desktop --resume <uuid>` (the runner offers to run it; it is the only flag combination Foreman uses, MASTER-SPEC §6). Claude Desktop should open on that session. Check that Desktop shows the earlier exchange.
3. In Desktop type the printed marker line (`S23-MARKER-…: what was the code word? Reply with it.`) and wait for the answer. Do not start another CLI session in that folder meanwhile.
4. `pnpm spikes s23 check` looks for the marker in the original transcript (shared), in new `.jsonl` files in the same project folder, and in Desktop's data under `~/Library/Application Support/Claude` (copied). Read-only.

Optional follow-up that settles "the CLI chain continues unaffected": in the work folder run `claude --resume <uuid>` and note whether the Desktop exchange is visible in the CLI session; `/exit`.

If `check` is INCONCLUSIVE (marker nowhere): Desktop may store the copy in a database. Look at the Desktop session list: is the session shown under the same id/title? List `~/.claude/projects/<folder>/` before and after and describe the difference by hand.

## Pass and fail

- **Shared (pass column of MASTER-SPEC §9):** the marker is in the original transcript file, same session id.
- **Copied (fail column):** the original transcript is unchanged and the marker lives in another file (a new `.jsonl` or Desktop's own storage).
- Neither is a defect; the point is which one Foreman must design for.

## Decision rule

| Branch | Foreman does | Documents changed |
| --- | --- | --- |
| Shared | the chain is handed off (`handed-off`); the next Foreman step forks (`--fork-session`, AC-F010-15) | ADR-008 (Desktop handoff: shared confirmed); `docs/scope.md` AC-F024-03 records "shared", AC-F010-15 stays; M4-29 test encodes the fork |
| Copied | no fork needed; the CLI chain continues unaffected | ADR-008 (Desktop handoff: copied; the `handed-off` status stays informational); AC-F024-03 records "copied"; AC-F010-15 loses its Desktop trigger (the fork remains for explicit use); M4-29 test encodes no-fork |
