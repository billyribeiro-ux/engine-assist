# S-8 · Graceful end, signals and forks (M0-16)

Class HARD · manual (Billy on his Mac) · ADR-008 · threats T-029, T-030 · ACs AC-M0-13 (S-8), AC-F010-04, AC-F010-11, AC-F010-15, SR-13, SR-14 · encoded later by `rearm::ctrl_c_then_exit_order` and `chain::fork_argv`.

**Question.** With text in the input box and with background work: does Ctrl-C then `/exit` end a session within 10 s, and what do SIGTERM and SIGHUP do? Does `--resume <uuid> --fork-session --session-id <new>` honor Foreman's id for the forked transcript? What is the re-arm latency?

## Run

```bash
pnpm spikes s8 argv                 # zero tokens
pnpm spikes s8 fork                 # two one-word sessions
pnpm spikes s8 exit                 # Ctrl-C then /exit, draft text in the input box
pnpm spikes s8 exit --background    # same, with a background `sleep 31337` running
pnpm spikes s8 sigterm              # this script sends SIGTERM 25 s after Claude's answer (--window <s>)
pnpm spikes s8 sigterm --background
pnpm spikes s8 sighup
pnpm spikes s8 all                  # all of the above in turn
```

Every session is one-word, in `$TMPDIR/foreman-spikes/s8/work`, with the hook logger on all events. The runner prints your keystroke steps before each session (you do the typing: it cannot write to the TUI), then records the exit code or signal, time from signal to exit, whether `SessionEnd` fired and with what payload, whether the transcript's last line still parses, and whether `sleep 31337` survived Claude (it is ended afterwards). Afterwards it asks what you saw. The re-arm latency Foreman will see is Enter on `/exit` to process exit: the runner reports the hook-to-exit tail precisely and asks you whether the whole thing took under 10 s; for a number, screen-record (⇧⌘5) the `exit` run and read the video.

The Ctrl-C sequence in Foreman (ADR-008) is: write `\x03`, wait 150 ms, write `/exit\r`. Do it by hand at that pace: Ctrl-C, one second, `/exit`, Enter.

## Pass and fail

| Part | Pass | Fail |
| --- | --- | --- |
| Graceful end, draft in input box | Ctrl-C then `/exit` exits with code 0 within 10 s and no extra prompt | stays open, asks for confirmation, or exits late |
| Graceful end, background work | same, with the background task running | same failures; note if Claude asks "background tasks still running" |
| Fork ID | `SessionStart` has `source: "fork"`, `session_id` = the id Foreman passed, `<new>.jsonl` exists, original transcript byte-identical | other id, no such file, or the original changed |
| Fork flag rule | `--resume x --session-id y` without `--fork-session` is refused; with it, accepted | accepted without it, or refused with it |
| Signals (information only) | measured, not graded: the spec forbids signalling a non-idle session without confirmation whatever the result | n/a |

## Decision rule

| Branch | Condition | Documents changed |
| --- | --- | --- |
| Pass | graceful end and fork IDs both pass | re-arm as specified; fork IDs chosen by Foreman. ADR-008 records S-8 pass; AC-F010-04, AC-F010-11, AC-F010-15 unchanged; tests `rearm::ctrl_c_then_exit_order`, `chain::fork_argv` as specified |
| Fail, graceful end | exit not clean or not within 10 s (or an extra prompt) | Billy ends the session himself, then Foreman relaunches: `docs/scope.md` AC-F010-11 (replaces the automatic end), AC-F010-04 records the branch, ADR-008 (Re-arm step 2, Exit path taken), `rearm::*` tests, native dialog copy in `docs/contracts/ipc.md` if the Continue wording changes |
| Fail, fork ID | forked transcript does not use the passed id | fork IDs become "the only new transcript after launch"; if ambiguous, a fresh chain with context: AC-F010-15, ADR-008 (Desktop handoff bullet), `chain::fork_argv`, SR-14 wording in `docs/requirements.md` |

The two failures are independent; the report records each branch separately.
