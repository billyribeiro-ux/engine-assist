# Foreman · Security and privacy requirements

Status: Stage 3, revised after the security review · 2026-10-19
Inputs: `docs/handoff/stage-02.md`; `docs/MASTER-SPEC.md` §6, §7, §8, §11, §12; `spec/council/r4-redteam.md`, `r5-resolution.md`, `r5b-freeze-review.md`, `r6-feature-specs.md`, `r8-nfr.md`.

This document turns Master Spec §12 into the complete, numbered list Foreman is designed against (Microsoft SDL: requirements come before design). For each requirement it names **where it's built** (the blueprint stage of Foreman's own build, plus the feature) and **the test that proves it**. The tests will carry these names; the Stage 4.6 tickets reference them.

**Reviews.** The Stage 4.3 threat model (`docs/threat-model.md`) raised 13 further findings, applied here as SR-24a and changes to SR-05, SR-30, SR-31, SR-44, SR-45 and SR-47. The security-reviewer agent read this list against the frozen spec and against published source code: tauri 2.12.4, tauri-build 2.7.3, tauri-utils 2.10.2, tauri-codegen 2.7.3, tauri-plugin-opener 2.7.2, portable-pty 0.9.0, notify 8.2.0, @xterm/xterm 6.0.0 and @xterm/addon-web-links 0.12.0, plus the strings in the Claude Code 2.1.303 binary. It found 1 blocker, 16 major issues and 12 minor issues; every one is applied below. Some claims rest on Claude Code's own documentation, which the review sandbox couldn't reach. Those are marked **verify in 4.2** and are settled by the Stage 4.2 ADRs or by spike S-1′.

**Threat posture.** Foreman runs on one trusted Mac for one trusted user. It reads and acts on content it doesn't control:
- project repos that Claude Code edits continuously;
- chat output pasted from claude.ai;
- the blueprint;
- each repo's Claude Code configuration and `.git/config`;
- terminal output produced by Claude.

It also spawns the most capable program on the machine, `claude`, with flags that decide what that program may do and whose account it bills.

The security model:
- **The user is trusted.**
- **Repo content, pasted content, terminal output and Claude Code's behavior are not.**
- **The webview is less trusted than the Rust core.** A compromised webview could type into a Claude session (`pty_write`), so the webview's inputs and dependencies are controlled (SR-24, SR-61).
